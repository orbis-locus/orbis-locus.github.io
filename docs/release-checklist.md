- ✅ 【必須】確認メールが知らない人にも届くか確かめる（2026-11-12：ORBiS 用 Gmail を SMTP に、Confirm email オン）。Supabase標準のメール送信は送れる数や宛先に制限があるので、届かなければ独自のメール送信（SMTP。Resend など）を設定する

- 【推奨】ブロック機能（特定の人からのフレンド申請・招待を受けない）
- 【推奨】フレンド申請・グループ招待の連打を止める（1日の回数の上限をサーバー側で）
- 【推奨】新規登録のボット対策（Supabase の CAPTCHA：Cloudflare Turnstile など）

## 5. セキュリティ・マルウェア対策
- ✅ 【必須】配るファイルは BOOTH だけから。説明書に「BOOTH以外で手に入れたファイルは開かないで」と書く（2026-11-12：booth/はじめにお読みください.txt と商品ページの文に）（書きかえたファイルを再配布されるおそれ）
- ✅ 【必須】他人のデータが表示される所（フレンドのキャラシ・グループ・ユーザー名・取り込んだテキスト）で、HTMLとして実行されないか点検する（XSS）→ 2026-11-12：アイコンの位置（iconCrop）と BGM の音量が部品の中にそのまま入っていたのを数字だけに、キャラの色は「#英数字」だけに（cssColor）。わなを仕込んだキャラを全テーマ・フレンド表示で開いて、何も動かないことを確認
- ✅ 【必須】サーバーに入る大きさの上限をサーバー側でも決める（アイコン画像・キャラシ1件・Storage の ui-assets はファイルの大きさと種類＝画像だけ）→ 2026-11-12：キャラシ1MB・1人60人、グループ200KB、画面の編集2MB、ui-assets は1枚5MB・画像だけ（19-limits.sql）。アイコンは前から80KB、立ち絵などは18で1枚5MB・1人100MB
- ✅ 【推奨】画面の編集モードの値（部品の住所・画像URL）に、CSSを壊す文字や外部の追跡用URLが入らないよう、保存時にチェックする（マスター・編集者しか書けないが念のため）→ 2026-11-12：表示するときに { } < > を消す（外の画像の URL は、マスターが選んだものなのでそのまま）
- 【推奨】RLS（サーバー側の見える範囲・書ける範囲）を全部の表で見直す。とくに有料化の前
- 【推奨】Supabase のパスワードの最低文字数・漏えいパスワードの拒否を設定で確認

## 6. サーバーの容量・費用・バックアップ
- ✅ 【必須】Supabase の無料枠の上限を確認：データベース約500MB。立ち絵が data URL でキャラシの中に入っているので、クラウド保存する人が数十人でいっぱいになるおそれ → 立ち絵は Storage に分けて置く／1人あたりの上限を決める → 2026-11-12 済み：画像は Storage の char-images（1枚5MB・1人100MBまで）、キャラシ1人分は約65KB→約9KB に
- ✅ 【必須】無料プロジェクトは長く使われないと一時停止される。止まった時の案内と、監視の方法を決める（GitHub が2日に1回見回る・止まったときの戻し方は docs/mail-setup.md）
- 【推奨】定期的なバックアップ（無料枠は自動バックアップが限られる）
- 【推奨】料金がかかり始める目安を把握し、上限（Spend cap）を設定する
